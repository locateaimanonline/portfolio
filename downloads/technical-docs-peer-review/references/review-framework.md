# Review framework

Apply the author's documented style guide and publishing rules before treating any example here as a rule. A useful review distinguishes a demonstrable error from a question that needs product or editorial confirmation.

## Publication and accuracy

- Confirm that the page addresses the requested change and identifies affected platforms, versions, roles, and permissions.
- Check links and media in their actual source context. A valid path is not enough if it leads to the wrong task or an outdated screen.
- Look for draft markers, unresolved review comments, disabled sections, or conditional content that could hide a required action.
- Check that examples, commands, and warnings cannot cause an unintended or unsafe result. Verify product claims from available evidence; ask when the evidence is absent.

## Reader route

- Choose the topic type that matches the reader's need: explanation for a concept, values for a reference, and ordered actions for a task.
- Put prerequisites before actions and describe the result or way to verify success.
- Test whether each step tells the reader where to start, what to select or enter, and what happens next. Keep branches and optional paths clearly identified.
- Use related links to connect a task to its parent workflow or next action. Prefer useful links over a fixed number.
- Request a screenshot or diagram when it removes a real navigation or comprehension gap. Check that alt text describes the relevant content and that private data is not exposed.

## Editorial pass

- Make the introduction direct and specific. Remove wording that only announces the existence of the page.
- Use precise verbs and consistent UI labels. Match the product's actual interface and style guide instead of enforcing one organization's word choice.
- Split dense sentences, remove repeated ideas, and keep list items parallel. Preserve technical meaning when proposing a rewrite.
- Flag capitalization, punctuation, spelling, and markup problems when they affect the published page; do not flood a review with personal preferences.

## Comment shape

Lead with the observed issue, explain its consequence, and suggest a concrete replacement or ask a specific question. Say what evidence supports the claim. If a point is uncertain, make the uncertainty visible rather than guessing.
